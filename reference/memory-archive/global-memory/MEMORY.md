# Global Memory

Feedback that has been distilled into the always-loaded rules (`~/Code/_private/claude-config/rules/`) is archived in that repo's `reference/memory-archive/` — the rule is canonical; don't re-add archived entries here.

## Feedback

- [feedback_messaging_vendor-escalation.md](feedback_messaging_vendor-escalation.md) — Vendor escalations: name the specific partner/entity directly, cut the impact/padding sentence, keep only the asked-for ask, "I"-led warm opener
- [feedback_webhook_secret_rotation.md](feedback_webhook_secret_rotation.md) — Scan for shared secrets (e.g. ArgoCD) before rotating a GitHub webhook; rotate all sharers together
- [feedback_no_dotenv.md](feedback_no_dotenv.md) — Don't use .env / godotenv for personal Go projects; document `export` commands in README instead
- [feedback_multi-step-prod-approval.md](feedback_multi-step-prod-approval.md) — For multi-step prod ops (TF blue/green, staged migrations), wait for explicit user approval between each PR/step
- [feedback_act-on-obvious-next-step.md](feedback_act-on-obvious-next-step.md) — Obvious, reversible task-completion step (e.g. the deploy PR for a fix just released) → just open it as a draft; don't ask first
- [feedback_argue-dont-fold.md](feedback_argue-dont-fold.md) — Pushback on a recommendation → argue the substance, volunteer the best counter to your own position, name what you're not conceding; folding on first challenge wastes the exchange they asked for
- [feedback_verify-ci-trigger-rules.md](feedback_verify-ci-trigger-rules.md) — Test/dummy PRs must change files that actually satisfy the pipeline's path/branch filters — read the rules first
- [feedback_grafana-promql-regex-interpolation.md](feedback_grafana-promql-regex-interpolation.md) — Wrap `${var:regex}` interpolation in PromQL backticks, not double quotes
- [feedback_verify-current-pr-state.md](feedback_verify-current-pr-state.md) — Establish a PR's CURRENT state (fetch + `gh pr view`/`diff`) before analyzing or acting; don't trust a stale remote-tracking ref
- [feedback_no_worktree_cleanup_offers.md](feedback_no_worktree_cleanup_offers.md) — Don't repeatedly offer/ask about worktree or branch cleanup at the end of responses
- [feedback_no_unsolicited_pr_comments.md](feedback_no_unsolicited_pr_comments.md) — Don't post PR/issue comments unless asked; report in chat. If asked, keep them terse
- [feedback_check-deploy-target-constraints.md](feedback_check-deploy-target-constraints.md) — Before building an image/sidecar for an existing pod, check node arch, occupied (shared-netns) ports, and base-image config layout up front
- [feedback_no_explanatory_code_comments.md](feedback_no_explanatory_code_comments.md) — Keep code/config comments minimal + short: none for what's readable in the config nearby or for why-added; a good comment states genuinely non-obvious behavior (e.g. OTel gauge → max_over_time). Rationale goes in the commit/PR
- [feedback_commit-type-dependency-pointer-bump.md](feedback_commit-type-dependency-pointer-bump.md) — Bumping a pinned dep/image-tag default is `chore`/`fix`, not `feat!` — the breaking bump belongs to the commit that changes the interface; don't double-count
- [feedback_verify-claims-against-source-not-docs.md](feedback_verify-claims-against-source-not-docs.md) — Verify factual/impact claims against the source (Dockerfile/config/code), not stale narrative docs (README/CLAUDE.md)
- [feedback_scope-before-machinery.md](feedback_scope-before-machinery.md) — Before building a general system for a category, count real instances; for one/few, propose vendoring/inlining first and surface the tradeoff early
- [feedback_no-hard-wrap-in-pr-bodies.md](feedback_no-hard-wrap-in-pr-bodies.md) — one line per paragraph/bullet in PR, issue and discussion bodies; never hard-wrap prose at ~70–80 columns
- [feedback_pr-body-present-tense-capitalize-resource-types.md](feedback_pr-body-present-tense-capitalize-resource-types.md) — PR descriptions in present tense ("both render" not "rendered"); capitalize K8s/CRD resource types (Namespace, Secret, ExternalSecret, Application)
- [feedback_check-feature-region-availability.md](feedback_check-feature-region-availability.md) — When a cloud feature works in one region/cloud but not another, read its doc for a "supported regions" note before debugging config/IAM; silent API accept ≠ feature available (verify the effect)
- [feedback_cheapest-interpretation-first.md](feedback_cheapest-interpretation-first.md) — "provide an example / let me look at one" wants the cheapest artifact (a link); don't build worktrees/merges/scripts on the elaborate interpretation without confirming
- [feedback_confirm-cause-before-remediating.md](feedback_confirm-cause-before-remediating.md) — Don't pin/revert the component that merely *differs* from the last good run until you've confirmed it's the cause (cosign v3.1.1 was correlated, not causal — the OIDC incident was)
- [feedback_prefer-native-primitive.md](feedback_prefer-native-primitive.md) — Before hardening hand-rolled extraction of a platform value, check for a first-class primitive (`${{ job.workflow_ref }}` vs decoding the OIDC JWT)
- [feedback_suppress-by-role-not-symptom-shape.md](feedback_suppress-by-role-not-symptom-shape.md) — Suppressing a bot's unwanted change: scope by the role of the thing being changed (repo shape, published-artifact vs consumer), not a regex matching the malformed value — the latter encodes the bug, not the policy
- [feedback_more-emoji-in-chat.md](feedback_more-emoji-in-chat.md) — The user likes emoji in our direct chat replies; use them more liberally in conversational responses (extends the drafted-message emoji guidance)
- [feedback_question-sets-to-colleagues.md](feedback_question-sets-to-colleagues.md) — Asking a colleague several questions over chat: plain lines not numbered lists, ask for "input" not answers, give a hypothesis to react to, no emoji, no closer that leaks a verdict, quote their own words
- [feedback_issue-status-updates.md](feedback_issue-status-updates.md) — Progress comment on a tracking issue: headings + bullets not prose, report the finding not the evidence, link the source, name the real disagreement plainly (don't soften it pre-emptively), cut to half
- [feedback_docs-omit-rejected-alternatives.md](feedback_docs-omit-rejected-alternatives.md) — Durable docs carry what a rule does + its invariants, never why an alternative was rejected or something excluded — that's PR-description material; keep it short
