When a user asks to "provide / show me an example", "let me look at one", or makes any low-effort, ambiguous request, default to the **cheapest artifact that answers it** — usually a link, PR number, file path, or one-liner. Do NOT build heavy machinery (create worktrees, merge branches, regenerate lock files, write scripts) on the most elaborate interpretation before confirming that's what they want.

**Why:** In the volcano-renovate session the user asked "the lock files should be regenerated by renovate — please provide one example i can look at." I read that as "hand-fix one PR's lock so I can see the result", created worktrees for two PRs, merged master into one, and was about to run `tofu init -upgrade`/`providers lock` by hand — interrupted twice. All they wanted was a **link to one failing PR**. The elaborate path also contradicted their actual intent (let Renovate own the locks).

**How to apply:** Pick the minimal interpretation first and deliver it in one step. If a request *could* mean "go build X," state the cheap answer and ask before building. Watch for the tell "so I can look at / see it" — that wants a pointer, not a constructed artifact. Related: [[scope-before-machinery]].
