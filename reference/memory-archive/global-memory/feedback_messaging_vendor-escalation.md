Drafting an escalation to the Volcengine/ByteDance **account team**, the user's edits stripped my draft in specific ways worth generalizing.

**Why:** My draft over-hedged (anonymized the customer, added a business-impact sentence, tacked on an extra ask). The user's sent version was more direct, named the customer, and kept strictly to the ask they'd said they wanted.

**How to apply (vendor / escalation messages):**
- **Name the specific partner/entity directly.** I hedged to "one of our customers"; the user wrote "We have a request from **MapTech** to enable…". (Note MapTech is *not* a customer — they're Kognic's China compliance **license-holder + partner**; see [[tos-audit-logs-mt]].) Don't reflexively anonymize the named party to the vendor — the vendor already knows the relationship, and the concrete name strengthens the escalation. (Still never leak internal/personal-repo names.)
- **Cut the impact/padding sentence.** The user deleted "This is holding up an important compliance commitment for us." Escalation urgency is implied by escalating; don't add a separate emphasis sentence.
- **Only the ask the user stated.** The user had said "I will ask for a timeline," so they removed my extra "if there's a recommended alternative in the meantime…" line. When the user names the specific ask, don't append bonus asks.
- **"I"-led ownership + warm opener.** "I want to escalate…", "Hi ByteDance team!" (name the vendor, exclamation), "Thanks" not "Thank you." Lowercase "compliance cloud" / "public cloud", not Title Case.
- **Frame the need as a concrete request** ("We have a request from X to enable Y") rather than an abstract "We need Y."

Consistent with [[Slack drafts — shorter, more tentative, more specific]] and the colleague-tone note: default shorter and less hedged than my instinct.
